## Phase 2A — True Horizon & Mountain-Shadow Sunset (#2)

Accounts for hills, valleys, and mountains blocking the sun _before_ theoretical flat-horizon sunset.

### Scope

- **Terrain Elevation Sampling (Free Open-Meteo Elevation API):**
  - Endpoint: `https://api.open-meteo.com/v1/elevation?latitude=...&longitude=...` (free, no API key required).
  - Given a pin's `(lat, lon)`, sample a ring of points along the sunrise/sunset azimuths (e.g. at 0.5 km, 1.5 km, 3 km, 6 km, 12 km) and compute the maximum terrain horizon elevation angle (`atan2(dElev, distanceM)`).
  - Cache horizon profiles by rounded grid (`~1 km`) in Postgres or API memory (terrain doesn't change).
- **Light Planner Integration:**
  - Show **"Effective Sunset / Sunrise"** alongside flat-horizon times when terrain blocks > 1° above the horizon (e.g. _"Mountain shadow at 16:48 · 24 min before flat sunset"_).
  - Render the terrain horizon silhouette subtly on the `LightPlanner` compass / `ScoutCompassOverlay` horizon line.

## Phase 2B — Sun-Synchronized Shoot-Day Auto-Sequencer (#4)

Upgrades Project Schedule (`apps/mobile/src/ui/project-planner.tsx`) from simple light sorting to a conflict-aware multi-stop sequencer.

### Scope

- **Auto-Sequence Algorithm (On-Device, Zero Routing API Cost):**
  - Inputs: a Project's saved locations, target `shootDate`, and each spot's `bestLight` + `bearingDeg` + `(lat, lon)`.
  - Scores candidate orderings by:
    1. **Light window fit** (Golden AM / Golden PM / Blue Hour / Midday / Overcast).
    2. **Straight-line travel penalty** between consecutive stops (`distanceMeters`), avoiding cross-city zig-zags.
    3. **Time-window conflict warnings** (flags when two spots share the exact same 35-minute Golden Hour window and are > 15 km apart).
- **UI:**
  - Replace/enhance **"Sort by best light"** with **"Auto-plan shoot day"** showing estimated light-window slots, distance between stops, and conflict badges.

## Phase 2C — Time-of-Day Crowd & Sound Profile (#6)

Gives videographers, sound recordists, and portrait photographers actionable _when-to-shoot_ rhythm data.

### Scope

- **Structured Acoustic & Crowd Fields (`advancedInputSchema`):**
  - Extend `advanced.conditions` in `packages/shared/src/scout.ts` with optional structured fields:
    - `noiseLevel`: `'quiet' | 'moderate' | 'loud' | 'variable'`
    - `quietHours`: e.g. `'early_morning' | 'midday' | 'evening' | 'night' | 'always'`
    - `crowdPeak`: e.g. `'morning' | 'midday' | 'afternoon' | 'sunset' | 'weekends'`
  - Keep existing `crowdNote` for nuance (e.g. _"Tram every 10 min; empty before 08:00"_).
- **Capture, Edit & Filter Support:**
  - Add compact pills in `capture/details.tsx` (Advanced section) and `edit/[id].tsx`.
  - Add **"Quiet / low crowd"** filter chip in `filters.tsx` and `/v1/feed` + `/v1/map`.

## Phase 2D — Moodboard-to-Location Matcher (#3)

Lets scouts find real-world locations matching a visual or compositional reference without turning ShootSpot into a social feed.

### Scope

- **"Find Spots Like This" (Metadata + Visual Similarity):**
  - **Step 1 (Metadata & Geometry Match, zero ML overhead):** Match records by `goodFor`, `bestLight`, `framing`, `focalLength35mm` band, and `terrain`/`access` similarity inside the selected radius/area.
  - **Step 2 (Lightweight On-Worker Image Embeddings, optional):** Compute compact color/texture or CLIP-style embeddings in `services/worker` (watch TrueNAS 512 MiB worker cap) and query nearest neighbors via Postgres `pgvector` when a user picks a reference photo from their gallery or an existing record.
